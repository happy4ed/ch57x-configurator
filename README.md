## 웹 버전 로컬 실행
WebHID 는 `https://` 또는 `localhost` 에서만 동작한다 (file:// 불가). 위 Pages 주소로 쓰면 되고,
고쳐 가며 볼 때만 아래처럼 띄운다.
```bash
cd web
python3 -m http.server 8000
# Chrome/Edge 에서 http://localhost:8000 접속
```
1. **키보드 연결** → 팝업에서 키보드 선택
2. 레이어 탭 선택 → 버튼/노브 클릭 → 동작 설정 → **적용**
3. **키보드에 업로드** (전체 레이어를 한 번에 전송)
4. 프로필은 브라우저에 자동 저장 + JSON 내보내기/불러오기 가능

## "일부 버튼 초기화" 버그 대응
펌웨어는 키마다 커밋 시퀀스(`03 aa aa` / `03 fd fe ff`)로 저장을 확정하고, **전송되지 않은 키는
기본값으로 되돌린다**(`docs/PROTOCOL.md` §2). 벤더 소프트의 "일부 버튼 초기화" 가 이것이다.

이 도구는 업로드 전에 **키보드의 현재 설정을 먼저 읽어**, 이번 프로필이 건드리지 않는 키는
읽은 값 그대로 되쓴다. 그래서 화면에서 비워 둔 키가 있어도 기기 설정이 지워지지 않는다.
읽지 못하는 기기에서는 **무엇이 지워질 수 있는지 묻고** 진행한다.

> 2026-09-13 까지는 이 도구도 **바인딩된 키만** 보내고 있었다(문서가 요구한 전체 전송이 코드에
> 없었다). 빈 프로필로 업로드하면 키패드가 통째로 먹통이 됐다. 위 방식으로 고쳤다.

## 웹 버전 기능 (완료)
- [x] 프로토콜 포팅: 키보드/미디어/마우스/지연/LED + **현재 설정 읽기(0xFA)** — `docs/PROTOCOL.md`
- [x] WebHID 연결 · 읽기/쓰기 양방향 · 3레이어 · 프로필 저장/내보내기/불러오기
- [x] 실기형 레이아웃 UI(모델별 키 배치, 노브 우측), 클릭→모달 설정
- [x] 상용구(텍스트 매크로), 다단계 매크로 시퀀스, 마우스(클릭/휠/이동/드래그), LED 설정
- [x] 기기 키/노브 개수 자동감지(`03 fb fb fb`) + 수동 선택, 키 캡처 입력, 레이어 간 복사

## 알려진 한계 (펌웨어 제약)
- **레이어 전환은 키에 재매핑 불가** — 레이어 순환(1→2→3)은 전용 push 스위치에 펌웨어로
  고정돼 있고, 키 바인딩 종류에 "레이어 전환"이 없음(벤더 앱·오픈소스 모두 동일). 펌웨어 교체 외 방법 없음.
- **LED·일부 기기는 되읽기 불가** — LED read 명령 없음. `0xfb` 미응답 기기는 개수 수동 선택.

## 윈도우 앱 (`windows/`)
웹으로 불가능한 OS 통합. 동일 `docs/PROTOCOL.md` 를 `Ch57x.Core` 가 그대로 구현한다.
- 트레이 상주 · 프로필 목록에서 즉시 전환 · 창 없이 동작
- 윈도우 시작 시 자동실행(HKCU Run · 관리자 권한 불필요), 등록 상태를 트레이 메뉴에 표시하고 깨졌으면 그 자리에서 복구
- HUD 오버레이(투명 · 클릭 통과 토글) · 프로필 백업/복원(zip) · 키 편집기
- 상세 구상은 `docs/WINDOWS-PLAN.md`
